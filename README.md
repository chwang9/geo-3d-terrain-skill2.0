# 三维真实地形生成器 (Geo-3D-Terrain)

> 输入任意地名（或经纬度，或 **GeoJSON 文件**），自动生成该范围的**真实三维地形网页** —— DEM 高程逐像素还原 + 卫星影像叠加 + 点/线/面图形贴地渲染 + Three.js 渲染，输出单文件离线 HTML（Three.js 已内嵌）。

## 💬 怎么对 AI 说（v3.1.1，复制即可）

在 WorkBuddy 里不需要记任何参数，直接这样说：

| 你说 | AI 会做 |
|------|---------|
| 「生成包河区的三维地形」 | 自动定位 + DEM + 影像 + 地标，出单文件 HTML |
| 「生成大蜀山的 3D 地形，要高清」 | 同上并加 `--clear`（纹理 4096 极限档） |
| 「把这个 GeoJSON 叠加成三维地形」 | 按包围盒定位，图形按真实高程贴地渲染 |
| 「生成黄山市全市三维地形」 | 市域级大范围，自动 2×2 分块纹理（等效 8192px） |
| 「再清晰一点 / 更立体一点 / 去掉地标 / 导出 GLB」 | 重跑 `--clear` / 调 `--exaggeration` / `--no-landmarks` / 导出模型 |

## ✨ v3.1.1 效果特性

- 真实高程（AWS Terrarium / SRTM）+ 真实卫星影像（Esri World Imagery），非程序化生成
- **大范围不再糊**（v2.10，v3.0 完整化）：单张纹理上限会把 16 km+ 范围压到 >4 m/px；
  现在**自动 2×2 分块**（等效 8192px，HTML 端合成一张大 CanvasTexture，其余管线零改动，
  市域可显式 3×3=12288px），源影像 zoom 随之抬升、编码自动改 AVIF 并按体积预算降质量；
  **网格同步增密**（DEM 分辨率约 3–4×）；**分块并行编码**（16.8→9.7s）。
  实测包河区全区（22.6×28.1 km，--clear）：贴图 11 → **3.44 m/px**、
  DEM 80.6 → 20.1 m/px、HTML ~29 MB
- **影像高清晰**（v2.6）：源影像自动取 z17 原生层（1.01 m/px），纹理自动匹配源像素，
  JPEG 4:4:4 色度不抽样 + 两段 USM 锐化 + 局部对比去灰雾，同屏细节约为旧版 2.1 倍；
  `--clear` 把纹理拉到 4096（1.52 m/px）作极限档（约 14 MB，仅需放大细看时用）
- **GeoJSON 叠加**：行政区划/园区边界/航线/点位按真实高程"贴"到地形上（面填充含内洞 + 有宽度描边 + 点标记 + 名称标签），随垂直夸张实时联动
- **拖拽叠加**：把 `.geojson` 文件直接拖进网页即可即时叠加（坐标需落在当前范围内）
- 垂直夸张实时调节（1×–10×，默认按相对高差自动推荐）
- 三种显示：卫星影像贴图 / 高程分层设色 / 网格线；另有等高线自动描线
- **地标系统泛化（v3.1.0）**：不再假设目标是山峰——城区/平原同样能标出城市、交通枢纽、湖泊河流、

- 地形底座、雾效、墨卡托精确配准、响应式布局（窄屏不溢出）
- **v2.9 页面业务工具**：**测距**（水平/高差/坡度/直线）、**任意两点高程剖面**（含累计爬升）、

## 🚀 快速使用

### 1. 准备环境（隔离 venv，不污染全局）

```bash
PY="C:/Users/wangch/.workbuddy/binaries/python/versions/3.13.12/python.exe"
VENV="C:/Users/wangch/.workbuddy/binaries/python/envs/geo3d/Scripts/python.exe"
"$PY" -m venv "C:/Users/wangch/.workbuddy/binaries/python/envs/geo3d"
"$VENV" -m pip install -q requests numpy Pillow jinja2
```

### 2. 一条命令出图

```bash
# 按地名
"$VENV" scripts/prepare_terrain_data.py \
  --place "大蜀山" --zoom 14 --grid 3 \
  --out terrain.json --out-html 大蜀山.html

# 按 GeoJSON（自动定位 + 自动选 zoom + 图形贴地叠加）
"$VENV" scripts/prepare_terrain_data.py \
  --geojson 瑶海区.geojson --out t.json --out-html 瑶海区三维地形.html
```

浏览器打开 HTML 即可。首跑约 1–2 分钟（z17 源影像需多下些瓦片），**有缓存后约 2–3 秒**；
输出约 6 MB（Three.js 与影像均内嵌，离线可看）；追求极致清晰加 `--clear`。
日志末尾会打印分阶段耗时（`meta.timings` 里也有），慢在下载还是 CPU 一眼可见。

### 3. 只改样式时重渲染（不重新下载）

```bash
"$VENV" scripts/generate_html.py --data terrain.json --out t.html --exaggeration 6
```

## 📋 常用参数（完整清单见 SKILL.md）

| 参数 | 默认 | 说明 |
|------|------|------|
| `--place` | — | 地名（中英文均可），与 `--lat/--lon`、`--geojson` 三选一 |
| `--lat` `--lon` | — | 直接给 WGS84 坐标，跳过地理编码 |
| `--geojson` | — | GeoJSON 文件（可多个）：按包围盒定位 + 图形贴地叠加 |
| `--geojson-crs` | wgs84 | `gcj02` = 高德/腾讯导出（自动转 WGS84，否则整体偏 ~500 m） |
| `--geojson-color` | — | 强制所有叠加图形用同一颜色 |
| `--max-dem-tiles` | 64 | GeoJSON 模式 DEM 瓦片预算（自动选 zoom） |
| `--zoom` | 自动 | DEM 层级（3–15）；地名模式默认 14，GeoJSON 模式自动 |
| `--grid` | 3 | 地名模式覆盖 N×N 个瓦片 |
| `--max-size` | 1024 | 网格最大边长（顶点密度）；分块模式下自动加倍到 2048（DEM 分辨率约 3–4×） |
| `--sat-max-size` | 自动 | 影像纹理最大边长（默认按源影像像素自动取，上限 2560；显式给值则按给定值） |
| `--max-sat-tiles` | 1200 | 影像瓦片上限，超出自动降低 zoom |
| `--clear` | — | 最高清晰度：纹理 4096（1.52 m/px），约 14 MB、首跑约 3 分钟 |
| `--sat-tiling` | auto | **大范围分块纹理**：auto = 范围长边/档位上限 > 4 m/px 时自动 2×2（--clear 时等效 8192px）；`1`=强制单张；`3`=市域级（等效 12288px） |
| `--tiled-max-mb` | 24 | 分块纹理体积预算（MB），超预算自动降编码质量 |
| `--no-sat` / `--no-landmarks` | — | 跳过影像 / 跳过地标（降级快跑） |
| `--landmarks` | 自动 | 地名模式 16，GeoJSON 模式 0 |
| `--geocoder` | auto | amap(需 `AMAP_KEY`) → nominatim → photon 依次兜底 |
| `--out-html` | — | 一步生成 HTML |
| `--exaggeration` | auto | 垂直夸张，缺省时按"高差≈世界宽度18%"推荐 |
| `--workers` | 12 | 并发下载线程数（>16 会被 Esri 限流反降） |
| `--sat-format` | jpeg | 影像编码：`jpeg`=默认(3.44MB/230ms)；`avif`=**2.20MB/618ms，小 36%**（产物 4.67MB，需 Chrome85+/Safari16+）；`webp`=2.96MB/1337ms |
| `--despike` | 100 | 高程坏点清洗阈值(米)：与邻域差超过该值的孤立像素用邻域均值修正（`0`=关）；占比 > 1% 时自动放弃，避免误伤真陡崖 |
| `--no-cache` | — | 禁用全部缓存：瓦片 / 地标 POI / 地理编码（默认 `~/.cache/geo-3d-terrain`） |
| `--dry-run` | — | 只算计划不下瓦片：层级 / 瓦片数 / 已缓存数 / 预计耗时 / 预计体积 |
| `--cache-prune DAYS` | — | 清理 DAYS 天前的缓存后退出（0=全清），不影响 three/ 工具链源码 |
| `--cache-max-mb` | 1024 | 缓存总盘上限，超出按最旧优先删除 |

## 🔧 工作原理

```
地名 / 坐标 / GeoJSON ──→ 定位（地理编码打分选优 | GeoJSON 包围盒 + 自动 zoom）
                                     ↓
               DEM 瓦片(并发+缓存) ──┐
               影像瓦片(高层级+精确裁切) ─┼→ 拼接/精确裁切/降采样/统计峰值
               Overpass POI(三端点并发竞速+缓存) ─┘      ↓
               GeoJSON(抽稀+配色)  ──┘   纹理增强（缩放→USM→局部对比→烤 hillshade→4:4:4 编码）
                                     ↓
                          base64 内嵌 → 单文件 HTML（Three.js 内嵌，离线可看）
```

### 数据来源

| 类型 | 来源 | 备注 |
|------|------|------|
| DEM | AWS Terrarium `elevation-tiles-prod` | `elev = R*256 + G + B/256 - 32768`，z ≤ 15 |
| 影像 | Esri World Imagery | 自动取到 DEM zoom+3（地名默认即 z17，自动选层封顶 z18），按 bbox 精确裁切；纹理尺寸由源像素反推，避免插值假细节。`--clear` 抬的是**纹理尺寸**（4096=1.52 m/px），源仍取 z17——实测再抬到 z18 只多 1.8% 细节却要 4 倍瓦片；想要这 2% 用 `--clear --sat-extra 4` |
| 地标 | OSM / Overpass | 必须带 User-Agent，否则 406 |

### GeoJSON 叠加的实现要点

| 部分 | 做法 |
|------|------|
| 面 | `ShapeUtils.triangulateShape` 三角化（支持内洞）后逐顶点采样高程 |
| 线 | 沿线按 DEM 分辨率加密采样，生成有宽度的"丝带"（不能用 `THREE.Line`，linewidth 多数平台失效） |
| 点 | 小球标记 |
| 联动 | 每顶点经纬度存在 `mesh.userData.ll`，夸张系数变化时重算 y，实时贴合地形 |

## ⚠️ 注意事项

- 高德/腾讯**瓦片/地理编码**坐标为 GCJ-02，脚本已换算为 WGS84 再取瓦片；
  **GeoJSON 文件**若也是高德/腾讯导出，必须显式 `--geojson-crs gcj02`
- 海洋/无数据区域用最低高程填充；整块无数据会明确报错
- Three.js 默认内嵌进 HTML，离线可看；只有显式 `--three cdn` 才需要联网
- 地标数量与质量取决于 OSM 数据覆盖，可能为空（不影响地形生成）
